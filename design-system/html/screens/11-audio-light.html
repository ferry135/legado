S2

播放页 · 默认无封面 与 亮色封面最坏情况

iv_bg 无默认内容 · 默认封面实测 #E5E5E6

左：进入页面即所见（iv_bg 空，纯播放面 + 封面圆暖棕占位）。右：排查实测最坏情况——默认封面 #E5E5E6 模糊后铺满 + 新纱。修复前（scrim_50）该状态白字仅 2.71:1；修复后按落地令牌实算，最坏处为胶囊 4.94:1，其余 ≥ 6.7:1，全部 ≥ 4.5:1。

2.71:1修复前 · scrim_50 + 亮封面 → 白字（排查实测 2.3~2.7） 16.3:1修复后 · 默认态 #F3F0EB 字 @ #141312 7.7:1修复后 · 最坏亮封面顶部（标题/章名 #F3F0EB） 4.9:1修复后 · 最坏亮封面胶囊字 #F3F0EB（纯白 5.6:1）
  • bg_player_scrim 取值依据：sRGB 合成后按 WCAG 实算——亮封面 #E5E5E6 叠 31% 黑（scrim_50）= #9D9D9E，白字 2.71:1；叠 70% 暖黑 = #4D4A48，#F3F0EB 7.73:1（纯白 8.79）；叠 85% = #2C2927，#F3F0EB 12.71:1（纯白 14.45）、次白 #B4B0AA 6.69:1。渐变（顶 70 / 中 75 / 底 85）让章节名与控制区最稳，封面暖光仍可感知，与 Spotify 类播放器的重纱做法一致。
  • 为何不用设计稿原值 42%（rgba(12,8,5,.42)）：08-system s13 的 .scrim 42% 是按默认深棕封面定的；排查已证明任意浅封面会击穿（2.3~2.7:1）。恒定暗面方案必须对「任意封面」兜底，故加深至 70~85%，方向与设计稿注记「暗色 scrim 上白字白控件，不随日夜间切换而异」一致。
  • 计算口径：Android alpha 合成发生在 sRGB 空间，再按 WCAG 2.x 相对亮度折算；本稿全部比值由 Node 脚本实算（见 S5 验证清单）。

  • 实施裁定注（与上两条路径偏差，待设计负责人确认）：实际落地未取 S5④ 一行式，而是删除 ReadMenu.kt 全部 8 行 FAB 运行时赋值（fabTint + 4×setColorFilter），终态完全交给 view_read_menu.xml 静态定稿形态（backgroundTint=surface_container + tint=on_surface + elevation 0，:157-160 等四处）——即本稿「XML 形态即终态，Kotlin 不再覆盖」；边界守护由静态 on_surface 无条件承担（等效本条建议守护的回退色，四明暗组合恒安全；非沉浸 textColor 与 on_surface 同值观感不变，差异仅沉浸模式下图标不随自定义纸墨色，对比仍达标）。偏差记录见 ReadMenu.kt:197-200 注释。
  • 沉浸面板不冲突：本修复只动 FAB 底色；沉浸模式下顶部/底部面板仍染正文背景色（ReadMenu.kt:185 :195 upPanelBackground），实心主题面圆钮浮于其上是刻意的层级对比（03-reader 稿面即如此）。
